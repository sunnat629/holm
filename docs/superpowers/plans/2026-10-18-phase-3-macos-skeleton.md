# Phase 3: macOS walking skeleton Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A thin, runnable macOS app. `cargo run -p holm-gui --locked` opens a window titled "Holm" that can create a vault (with a strength meter), unlock it (showing the throttle wait), list items, add, edit and view a login, copy its password, lock by hand, and lock itself when idle or minimised. Done when, on a real Mac, create → add → lock → unlock → see item works by hand and the same flow passes headless in `egui_kittest`.

**Architecture:** a new `holm-gui` crate (binary plus a small library for tests) on eframe 0.37 with the `glow` renderer. It talks to the vault only through `holm_core::Session<holm_platform::FsStore>`. Argon2 work (create, unlock) runs on a worker thread that takes the `Session` by value and sends it back over an `mpsc` channel, so the UI never blocks and the session has one owner at a time. Secrets are typed into Holm's own `SecretField` widget (never `TextEdit`), held in a pre-allocated wiping `SecretInput` (not `SecretBuf`: that name is `holm_crypto::SecretBuf`), and painted as dots. Lock means dropping the unlocked view state and calling `Session::lock`. The vault lives at `~/Library/Application Support/Holm/holm.vault`, found by a std-only `holm_platform::paths` module. A std-only `holm_platform::lock` module takes an exclusive lock on `holm.lock` in the same directory for the life of the app, so a second Holm cannot open the same vault. eframe and arboard are macOS-only target dependencies, so the workspace still builds on Linux and Windows, where the binary prints that the GUI is macOS-only for now.

**Tech Stack:** Rust 1.99.1, edition 2024. New runtime deps (macOS target only): `eframe =0.37.0` (`default-features = false`, `features = ["glow", "accesskit"]`; egui comes through `eframe::egui`, no direct `egui` dep), `arboard =3.7.0` (`default-features = false`). Dev (macOS only): `egui_kittest =0.37.0` (`default-features = false`). Dev (every OS): `tempfile`, `static_assertions` (both already in `[workspace.dependencies]`). Existing: `holm-core`, `holm-crypto`, `holm-platform`, `zeroize`. The single-instance lock adds no crate (std `File::try_lock`, stable since Rust 1.89). Data: Atkinson Hyperlegible Next and Atkinson Hyperlegible Mono (OFL-1.1). Guide: `docs/learn/gui/README.md`.

**Spec:** `docs/superpowers/specs/2026-10-17-holm-v1-design.md` (§8.0 default path, §9, §10 GUI, §11 throttle, §14 Phase 3). UI: `docs/design/ui-final-notes.md` (StrengthMeter, unlock copy, create checkbox). Decisions: `docs/DECISIONS.md`. Builds on the merged Phase 2a (`docs/superpowers/plans/2026-10-18-phase-2-holm-core.md`, including `Session::active_items` from Task 10).

## Global Constraints

- Phase 2a is merged first (branch `phase-3` is cut from `origin/phase-2` and moved with `git rebase --onto main` after the Phase 2a PR squash-merges). Phase 3 changes no file format, no crypto and no `holm-core` behaviour; any core change it needs is a separate, Opus-reviewed commit.
- **Security floor (owner ruling, binding):** no plaintext on disk (only the encrypted vault and its temps); every secret in a wiping type (`SecretInput`, `SecretText`, `MasterPassword`, `Zeroizing`); no logging of secrets; every unlock goes through `Session::unlock` and so through `Throttle`. The GUI never reads the vault file or calls `envelope` directly.
- Licence `MIT OR Apache-2.0`; `[lints] workspace = true`, so `unsafe_code = "forbid"` covers `holm-gui`. `#![forbid(unsafe_code)]` and `#![deny(missing_docs)]` in `lib.rs`.
- Secret entry uses `SecretField` only. `egui::TextEdit` is allowed only for title, username and URL, each backed by a `Zeroizing<String>` pre-allocated to `holm_core::rules::MAX_LINE_BYTES` with `char_limit(MAX_LINE_BYTES / 4)`, so it never reallocates. Constants come from `holm_core::rules::{MAX_SECRET_BYTES, MAX_LINE_BYTES}` (`holm_core::item` does not export them) and `holm_core::settings::REHIDE_PASSWORD_SECS`; auto-lock time comes from `session.settings()`. No UI text hard-codes "30 s" or "5 minutes".
- eframe features exactly `glow` and `accesskit`. Off: `default_fonts`, `persistence`, `clipboard`, `wgpu`, `wayland`, `x11`, `web_screen_reader`, and the eframe defaults `links` and `system_fonts`; `winit/default` is off too. `App::save` is not implemented. `cargo tree -p holm-gui -e features --target aarch64-apple-darwin --locked` must show none of the off features (including `links`, `system_fonts` and `winit/default`).
- **Platform gating:** `holm-gui` modules are gated one by one with `#[cfg(target_os = "macos")] pub mod …`, never with a crate-level `#![cfg]`. Every file under `crates/holm-gui/tests/` (and `tests/common/mod.rs`) starts with `#![cfg(target_os = "macos")]`, because `cargo test --workspace` runs on the 3-OS CI matrix. Unit tests that use egui sit in macOS-gated modules.
- **Test fonts:** `default_fonts` is off and kittest panics on missing glyphs, so every harness (unit and integration) is built with `Harness::builder().with_context_setup(holm_gui::fonts::install_fonts)`. `allow_missing_glyphs` is never used.
- No log backend and no `tracing` subscriber: `holm-gui` depends on no `env_logger`, `tracing-subscriber` or similar. No `println!`/`eprintln!`/`dbg!` of anything from the vault. Every type holding item or secret data has a hand-written `Debug` with lengths only.
- Window title is always `"Holm"`. Item titles never go into the title, notifications or OS recent-items lists.
- Every error message shown is fixed text from `holm-gui`, never a path, a field value or a library error's `Display`.
- Every new dependency goes in root `[workspace.dependencies]` with an exact `=` pin and passes `cargo deny --all-features --locked check` and `cargo vet --locked`. `--locked` on every cargo command. Vet: `holm-core` and `holm-crypto` get no exemptions for normal (non-dev) dependencies. The `holm-core`, `holm-crypto` and `holm-platform` dependency trees do not change: `cargo tree -p holm-core -e normal --locked` is identical before and after Task 1 (no GUI crate ever reaches the core).
- Tests use `KdfParams::FLOOR`, a tempdir vault and fake data only (`example.com`, values containing `EXAMPLE`). The binary uses `KdfParams::DEFAULT`.
- `clippy -D warnings` and `rustfmt --check` clean. Commit first, then `scripts/ci-local.sh` must print `ALL GATES PASSED` before every push. GitHub Actions is manual-only and never the gate.
- One GitHub issue per task (labels `phase-3`, `security`, `lesson`), listed in `docs/tasks/BACKLOG.md`. Every task writes one lesson in `docs/learn/` (numbered from 22, same five-part format as Phase 2, under 250 lines) and adds its line to `docs/learn/README.md`.
- **Process (2026-10-18):** review depth follows risk. Opus reviews crypto, password, file-format and `unsafe` work: here Tasks 1 (supply chain), 2, 3, 4, 5 and 6. ## Security decisions

Proposed by the planner for the security COS; each becomes a line in `docs/DECISIONS.md` when its task lands.

- **Security decision (GUI dependencies):** eframe with `glow` and `accesskit` only, arboard without default features, both macOS-only target dependencies. eframe's `clipboard` feature stays off: it pulls arboard's image decoders (11 extra crates, including tiff and jpeg parsers). Holm calls arboard itself, plain text only. AccessKit stays on because spec §10 requires screen-reader support (3 extra crates).
- **Security decision (clipboard in Phase 3):** copy uses arboard with `SetExtApple::exclude_from_history()` (macOS `org.nspasteboard.ConcealedType`, best effort). There is no auto-clear yet; the button's confirmation says so. `NativeOptions::clipboard_shortcuts = false`, so egui never turns Cmd+C/X into copy events: nothing in Holm's window can be copied except through the Copy button. Cmd+V is handled by Holm: into a `SecretField` straight from arboard into the wiping buffer (the arboard `String` is wiped after), into a plain field as an injected `Event::Paste`.
- **Security decision (revealed text):** a revealed password is drawn with an egui label, so egui's text layout holds a non-wiping copy until its cache drops it. The label is `.selectable(false)`, so egui selection and Cmd+C cannot take it, but the text still reaches the AccessKit tree (as the label node's value) and the galley cache while shown. Reveal hides after `holm_core::settings::REHIDE_PASSWORD_SECS`, on focus loss and on lock. Spec §10 already says the widget reduces copies and cannot promise none; `docs/CRYPTO.md` records the leak (Task 7).
- **Security decision (plain fields):** title, username and URL use `TextEdit`, which keeps an undo history in plain `String`s. These are display fields, not secrets (spec §8 item text rules); the gap is written down in `docs/CRYPTO.md`.
- **Security decision (vet for GUI crates):** the current rule allows exemptions only for dev-only or unused-target crates. About 87 new runtime crates (macOS) arrive. Order: imports first (`cargo vet regenerate imports`); then `cargo vet trust` only for publishers an imported set already trusts; every `trust` entry gets an explicit `end` date before the Phase 6 release; whatever remains gets an exemption whose note reads exactly `gui-only, pre-release; audit or replace before Phase 6`, listed in `docs/DECISIONS.md`. `holm-core` and `holm-crypto` get no exemptions for normal (non-dev) dependencies. Needs a COS yes before Task 1 merges (it widens the exemption rule).
- **Security decision (single instance):** the GUI takes an exclusive, non-blocking std `File::try_lock` on `<vault dir>/holm.lock` (mode 0600) at startup and holds it for the life of the app (`holm_platform::lock::InstanceLock`, no new dependency). A second Holm shows fixed text and never opens the vault. Why: two windows on one vault can overwrite each other's saves. The lock file is empty and holds no secret; the vault directory therefore holds `holm.vault` and `holm.lock`.
- **Security decision (font licence):** OFL-1.1 is not added to `deny.toml`. `cargo deny` checks crates, and the fonts are data files covered by `LICENSES/OFL-1.1.txt`, `NOTICE` and the hashes in `scripts/ci-local.sh`.

- The vault directory must hold only `holm.vault` and `holm.lock` after create, add, lock and quit (no temps), with modes 0700 (directory) and 0600 (both files), and the vault bytes must not contain the item's title or password → tests in Task 1 (`vault_dir_is_owner_only`, `world_writable_dir_refused`, `lock_file_mode_0600`) and Task 7 (`no_plaintext_on_disk`).
- A second Holm on the same vault must show fixed text and never open the vault → tests in Task 1 (`second_acquire_is_held`) and Task 3 (`second_instance_shows_fixed_text_and_no_vault`).
- Idle for the auto-lock time from the settings (default 300 s) must lock even when no frame runs `ui`, and minimising must lock at once; a manual lock with unsaved changes must ask first, an idle or minimise lock must never wait → tests in Task 6.
- A revealed password must hide after `REHIDE_PASSWORD_SECS`, on focus loss and on lock; while hidden no AccessKit node (label, value or description) holds it, and while shown it appears only in the reveal label → tests in Task 4 (`no_node_holds_password_while_hidden`, `reveal_leaks_only_in_label`) and Task 6.
