UX audit of the first mock

The baseline mock gets the structure right: three panes, honest first-run copy, a working throttle state and a separate cost error. These are the problems found, ordered by risk. P0 items affect trust or security honesty, P1 items affect flow, P2 items affect access and polish. Each one is fixed in the Screens tab.

  1. P0Lock statesLocked and Unlock are two screens, so getting back in takes an extra click and the "locked" view hints that something is still loaded.Fix: one unlock screen with a reason line (idle, sleep, manual). Spec §10: locked state shows only the unlock screen.
  2. P0Honest copyThe status bar says "Clipboard: empty" and the lock view says "Clipboard was cleared". Holm cannot know either one.Fix: show a clipboard segment only while Holm's copy is pending. After lock, say "Holm's copy was removed" only if it was still there.
  3. P0Honest copy"Wrong master password." hides the other cause. A tampered file gives the same error (spec §6).Fix: "That password didn't open this vault. Either the password is wrong, or the file was changed or damaged."
  4. P0Dangerous actionsDelete forever and Empty trash act on one click. The copy never says that old copies and backups keep the data.Fix: confirm modal, Cancel focused, Enter never confirms, honest scope text (spec §7).
  5. P0Shoulder-surfingReveal is a sticky toggle with no visible timer, and the note says "hold to reveal" while the mock does something else.Fix: one rule. Show toggles on, the value gets an amber frame and "Visible · hides in 30 s", and it hides on timeout, item change, lock or window blur. Mask is always 12 dots, so length doesn't leak.
  6. P0Data lossNothing says what happens to an unsaved edit when auto-lock fires.Fix: edits are discarded on lock (security first). The status bar turns amber 30 s before lock, and the unlock screen says what was discarded.
  7. P0ErrorsSave failure is a full-page "Something went wrong" that throws you out of the editor.Fix: inline banner in the editor with your input kept, the cause, "the file on disk is unchanged", Try again, and Save a copy elsewhere. The status bar shows "Not saved".
  8. P0Spec driftThe default path is ~/Documents/Holm. Spec §8.0 uses the per-OS app data folder.Fix: ~/Library/Application Support/Holm/holm.vault on macOS, with the Windows and Linux paths in notes.
  9. P1Information architecture"+ New item" sits in the menu pane. Filters are two dropdowns, there is no sort, and the spec's category chips are missing.Fix: the sidebar holds types, Favourites and Trash. The list holds search, category chips, sort and New (spec §10).
  10. P1First runThere is no welcome choice, no success state, no next steps and no empty-vault state.Fix: Welcome (create or open), Vault created (add item, import, back up), and an empty vault with two clear actions.
  11. P1Create form"Passwords do not match" shows while you are still typing the first field, and the meter uses colour alone.Fix: check the match on blur of Confirm or on submit. A four-segment meter plus a word label plus zxcvbn feedback, and one acknowledgement that Holm can't recover the password.
  12. P1KeyboardNo shortcuts and no Enter or Esc rules, and focus order is unspecified.Fix: a shortcut map (Build notes), autofocus on secret fields, Enter submits safe forms only, Esc cancels or hides.
  13. P1Recovery phraseThe phrase shows as one long line inside the password modal. It is hard to copy by hand and has no visible timer.Fix: the modal asks only for the password. The phrase then shows as a numbered 3×4 grid in the detail pane with a 60 s countdown and Hide now.
  14. P1SettingsThe copy says weakening needs the password, but no flow is drawn.Fix: a confirm modal names the old and new value and asks for the master password. Options have a ceiling and no "Never".
  15. P1ImportOnly row-level issues are shown. File-level errors (too large, wrong columns, not UTF-8) and the done state are missing.Fix: four error states, a preview that never shows values, and a done state that tells you to delete the source file.
  16. P1Change passwordAfter the change there is no nudge to replace backups, which still open with the old password.Fix: the done state offers "Save a new backup copy" first.
  17. P2AccessibilityType icons are two-letter codes ("Lg", "Cr") and favourite is "*". Danger relies on a red outline.Fix: a distinct icon shape per type plus a text type in the row, a star with an AccessKit name, and danger buttons with icon, verb and placement.
  18. P2AccessibilityModal focus can leave the modal, and focus on rows is not separate from selection.Fix: egui::Modal plus a Tab-wrap check, and a 2 px inset focus ring separate from the selection fill.
  19. P2PrivacyWindow titles like "Holm - Edit item" leak activity to screen-share pickers and window lists.Fix: the window title is always "Holm".
  20. P2Crypto UXAddresses show as one block, with no help against clipboard-swapping malware.Fix: group the address in 4s, and after copying, prompt to check the first and last characters.
  21. P2Copy toneMessages like "Something went wrong" appear, separators are mixed, and "Show..." vs "Show" is inconsistent.Fix: say what happened and what to do next. Use "·" as the separator. An ellipsis means the action asks for more input.
  22. P2Status barThe status bar shows an item count and the full path. Neither is state you act on.Fix: lock state, auto-lock countdown, clipboard countdown, save state and file name.

Design system

Small on purpose. Every value maps to one field of egui's Style, Spacing or Visuals, so the builder sets it once in a holm_gui::theme module and uses stock widgets for the rest. This is egui's default look with higher contrast, one accent and calmer greys.

Type

Bundle two OFL fonts, Atkinson Hyperlegible Next for UI and Atkinson Hyperlegible Mono for secrets, with egui's default fonts as fallback. The Braille Institute drew them so that 0/O and 1/l/I are distinct, which matters when someone types a password from the screen. Each is about 60 to 90 KB after subsetting to Latin. egui has no line-height setting, so the row height comes from interact_size.y.

egui Spacing and shape

  • item_spacing = (8, 8)
  • button_padding = (10, 5)
  • interact_size = (40, 28). Mobile later: 44
  • window_margin = 16, menu_margin = 8
  • scroll.bar_width = 8, always visible in lists
  • Corner radius: widgets 4, banners 6, windows/modals 8, chips 12
  • Shadows: modal only (window_shadow 0,12 blur 32). Panels flat
  • Animation time 0.08 s; respect OS reduce-motion (no spinner rotation)

Neutrals carry a slight blue bias towards the accent. Every text pair meets WCAG AA (4.5:1), and input borders and focus rings meet 3:1 against their surface. Semantic colours never stand alone: each banner tone has its own icon shape and a bold title.

Icons

egui ships no icon font we'd want to rely on. Holm vendors a 26-glyph subset of Phosphor Regular (MIT) as one small TTF (about 8 KB), loaded as FontFamily::Name("icons") and drawn with RichText. There is no extra crate (no egui-phosphor), so the dependency tree doesn't grow. The subset is built once with pyftsubset and committed with its licence and a script to regenerate it. Rules: an icon never stands alone without a hover text and an AccessKit label, each item type has a different shape, and banner tones have different shapes (circle-i, triangle, octagon, check). The page below draws stand-ins in the same style.

Live specimens use the same tokens as the screens. "Stock" means a stock egui widget with theme values. Custom means Holm draws it.

Password field Custom SecretField

  • Looks like a TextEdit: 30 px, line-strong border, field fill, Monospace mask.

Danger button (stock Button with fill)

  • Filled danger: only for actions that can't be undone in Holm (Delete forever, Empty trash, Export CSV). Always inside a confirm modal, always on the right, never focused by default.
  • Outline danger: reversible actions (Move to Trash), with Undo for 10 s.
  • Label = icon + exact verb + object. Never "OK" or "Yes".
  • Enter never activates a filled danger button. Space or a click only.

Banner (stock Frame)

  • Tones: info, warn, danger, ok. Each has its own icon shape and a bold first sentence.
  • Text is always fg on the tinted fill (AA in both themes). Actions sit inside the banner.
  • Placed where the problem is: above the form, never as a floating toast. AccessKit live region "polite"; danger is "assertive".
  • Messages say what happened, then what to do. They never contain secrets, item values or file contents.

Delete "Old forum login" forever?

It's removed from the vault file the next time Holm saves. Older copies and backups of the file still contain it.

Modal (stock egui::Modal, egui 0.30+)

  • Dimmed backdrop (scrim), 460 px max, 16 px padding, Heading title, body, actions right-aligned: secondary then primary.
  • Focus starts on the first field, or on Cancel for confirms. Tab wraps inside; check egui's behaviour and add a wrap if needed.
  • Esc = Cancel (except while working). Clicking the backdrop does nothing, so a stray click can't lose input.
  • While working (Argon2), the buttons are disabled with a spinner and Esc is ignored.

Status bar (stock TopBottomPanel::bottom)

  • 28 px, Small text, tabular digits, side fill. Left: lock state and auto-lock. Middle: clipboard (only while Holm's copy is pending). Right: save state and file name (full path on hover).
  • Repaint once a second with request_repaint_after, and only while a countdown is visible.
  • Last 30 s before lock: amber text plus clock icon, plus "Unsaved changes will be discarded" when editing.
  • Clipboard: "Clear now" clears only if Holm's value is still there. AccessKit announces only the start and end, not every tick.

Category chip (stock SelectableLabel, styled)

  • 24 px pill. When selected: accent-weak fill, accent border, check icon and SemiBold (three cues, not colour alone).
  • Single select. Arrow keys move between chips; Space selects.

Custom egui widgets needed

  1. SecretField: single-line secret input (spec §10). Wiping buffer, mask layout, no undo, no AccessKit value, eye toggle with timeout.
  2. SecretTextArea: multi-line variant for note bodies and phrase entry. Same rules, plus line wrap of mask glyphs.
  3. SecretDisplay: read-only shown value from the wiping buffer, not selectable, amber frame, countdown. Its PhraseGrid mode draws numbered words.
  4. ItemRow: two-line selectable row with type tile and star, own AccessKit node.
  5. StrengthMeter: 4-segment painter bar plus label (small).

Everything else is stock: SidePanel, CentralPanel, TopBottomPanel, ScrollArea, Button, SelectableLabel, ComboBox, Checkbox, RadioButton, Slider, DragValue, TextEdit (non-secret fields only), Frame, Modal, Spinner. Native file dialogs through rfd.

Security calls settled here (per spec)

  • Reveal timeouts: passwords 30 s, recovery phrases 60 s. Secure-note bodies stay shown until you leave the item, the window loses focus, or Holm locks. All of them hide on window blur.
  • Shown secrets are not selectable; copying goes only through Copy, so auto-clear and the clipboard-history hints always apply.
  • Screen readers get the field name and state, never the value (spec §10). Copy is the accessible route, and the docs say so.
  • Recovery phrase copy exists only inside a shown session that you opened with the password. It uses the same 30 s clear and is never the default.
  • Ceilings, no "Never": auto-lock at most 60 min, clipboard clear at most 90 s. Lock on sleep can be turned off only with the password.
  • Enter never confirms a destructive action, and Cancel holds focus in every confirm.
  • Unsaved edits are discarded on auto-lock, with a 30 s amber warning and a note on the unlock screen.
  • Window title is always "Holm". No item names in titles, notifications or recent-items lists.
  • Masks are a fixed 12 dots, whatever the real length.
  • Crypto addresses show in clear (you need to check them). Note bodies start hidden.
  • The throttle notice appears after the first wrong try; the countdown appears on the third. The UI never says the wait resets on restart (the docs do).
  • Item type is fixed after creation, so fields can't be silently dropped.
  • CSV export leaves out Trash, and the dialog says so.
  • Opening another vault locks the current one first.
  • Cost errors hide the password field: Holm didn't try the password, so asking for another is pointless.

Carrying it to mobile

  • Three panes → list, then pushed detail (resize this page to phone width to see the stack).
  • Sidebar → a filter sheet and a bottom bar with Vault, Generator, Settings.
  • Status bar → a slim strip above the bottom bar for the clipboard countdown; auto-lock reads "Locks when you leave Holm".
  • Modals → full-height sheets; the same copy and button order.
  • Shown secret, amber frame and countdown map one to one. Copy stays a button; no long-press copy.
  • Targets grow from 28 px to 44 px; type sizes stay the same.

Default vault paths (spec §8.0)

  • macOS: ~/Library/Application Support/Holm/holm.vault
  • Windows: %APPDATA%\Holm\holm.vault
  • Linux: ~/.local/share/Holm/holm.vault

The status bar shows the file name and gives the full path on hover. The UI config holds only the theme, window size and last path.
