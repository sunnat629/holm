## 3. Where Holm is different

- **Advantage: no network code at all, enforced by tooling.** Even KeePassXC ships an update check, favicon downloads and a browser socket. Every cloud product exposes a server. The 2026 ETH Zurich paper found 25 attacks across Bitwarden, LastPass and Dashlane, all needing a malicious server; that attack class does not exist for Holm [S15].
- **Advantage: modern, conservative crypto defaults.** Argon2id at 256 MiB beats KeePassXC (Argon2d, 64 MiB), Bitwarden (PBKDF2 600k, or Argon2id 32 MiB), Dashlane (Argon2d 32 MB) and 1Password/LastPass (PBKDF2). XChaCha20-Poly1305 with the whole header as AAD avoids the CBC+HMAC constructions Cure53 flagged as ad hoc in Bitwarden [S13].
- **Advantage: bounded KDF costs before any work.** Cure53's 2025 review of Bitwarden's crypto crate noted it enforced minimum KDF values but no maximum, which allows denial of service [S13]. Holm's floor and ceiling cover both sides.
- **Advantage: first-class recovery phrases.** Only 1Password has a dedicated crypto wallet item; Proton has a template; the rest use notes. Holm's re-auth to reveal or copy is stricter than any of them.
- **Advantage: memory-safe core and lessons already learned.** KeePass's CVE-2023-32784 came from a custom password box leaving strings in managed memory [S8]; Holm's wiping secret widget targets exactly this. KeePassXC's disputed CVE-2023-35866 is closed by Holm's re-auth for settings changes [S4].
- **Gap: password is the only factor.** A stolen Holm file is only as strong as the password. 1Password's Secret Key makes offline cracking of a stolen vault impractical, and KeePassXC, KeePass and Enpass offer key files or hardware keys.
- **Gap: features people expect.** No sync, mobile, autofill, browser extension, TOTP, passkeys or attachments in v1. Every listed product except Vaultwarden has most of these. Holm will appeal to a narrow, security-first audience at first.
- **Gap: no track record and a new file format.** KeePassXC has a public audit and an ANSSI certification; Bitwarden published about nine audits in 2025 alone [S2][S3][S14]. Holm has neither, and its format has no other readers, unlike KDBX (KeePassXC, KeePassDX, KeePassium, Strongbox). CSV export is the only exit.

## 4. Ideas worth taking

- **[Security] Optional key file as a second factor.** From KeePass, KeePassXC and Enpass, and the idea behind 1Password's Secret Key. A 256-bit random file mixed into the KEK input (for example HKDF over Argon2 output plus file hash) makes a stolen vault uncrackable without the file. The header flags field already leaves room. Could be v1.1, but reserve the flag and KDF input order now.
- **[Security] Upgrade KDF costs on unlock.** Bitwarden warns accounts below 600k iterations, and LastPass's old accounts were never forced up, which hurt victims after the 2022 breach [S11][S34]. When a vault opens with costs below the current default, offer (or do) a re-key with new costs on the next save.
- **[Security] A memory-dump test for the master password.** CVE-2023-32784 was found by dumping KeePass memory and searching for password fragments [S8]. Add a CI test on each OS: unlock, lock, dump the process, search for the password and a known secret. It turns the "reduces copies" claim in section 10 into measured evidence.
- **[Security] Harden the release pipeline, not just the code.** The April 2026 Bitwarden CLI compromise came through a compromised CI action [S16]. Pin every GitHub Action by commit SHA, use short-lived signing credentials, require two-person approval for release tags, and keep signing keys off CI where possible.
- **[Security] Protect users from fake downloads.** KeeLoader was a validly signed trojanised KeePass spread through search ads [S9]. Publish one canonical download domain, the minisign/Sigstore identity in the README and SECURITY.md, and a short "verify your download" page. Consider registering obvious lookalike domains.
- **[Security] Offline password health report.** 1Password's Watchtower and similar tools are cloud-tied, but weak, reused and old passwords can be found locally with the zxcvbn already in the spec. Breach lookups (HIBP) stay out because they need network.
- **Import from KeePass (KDBX 4) and plan for FIDO CXF.** KeePassXC users are Holm's most likely audience; KDBX import lowers the switch cost. The FIDO Credential Exchange Format reached Proposed Standard (errata March 2026) with 1Password, Bitwarden and Dashlane as editors [S50]; a later CXF export would give a standard, less lock-in exit than CSV.
- **Printable "emergency kit".** 1Password gives every user a sheet with recovery details. For Holm: a one-page PDF/print view with the vault location, backup advice and a box to write the password, never auto-filled. Losing access is the most likely real-world failure for a local-only vault.
